# 前端技术适配声明：奶油贴纸日历与饮印册

## 项目判断

- 产品：面向喜爱奶茶、咖啡与生活记录用户的本地优先移动 App。
- 主要终端：iOS 与 Android；当前工程为 React Native 0.87.1，不改造成 Web 项目。
- 本阶段目标：完成“照片 → 信息补全 → 免费滤镜 → 保存 → 日历贴纸 → 店铺色票”的真实本地闭环。

## 技术适配

- 继续使用 TypeScript strict、React Navigation、OP-SQLite、React Native Skia 和 feature/domain/infrastructure 分层。
- SQLite 是本阶段饮品记录、日历和印章解锁的事实来源。糖度、温度/冰量使用 Schema V2 增量迁移，兼容既有 V1 记录。
- 表单不新增表单库：当前字段规模仍适合局部 React State；保存前校验店铺、饮品与类型、糖度、温度四项，失败保留所有输入。
- 免费滤镜继续端侧运行；AI 艺术生成未接入前不伪造任务结果。后续接入时必须增加 submitting/queued/running/succeeded/failed、幂等和失败返还。

## 视觉与原创边界

- 使用已确认的奶油纸张、照片贴纸、柔和粉/黄/蓝与海报拼贴方向，日历是首页第一视觉焦点。
- 参考图中的圆形地名章和英文椭圆章不复刻。产品采用原创“饮品色票”：齿孔矩形、DD 角标、店名字首、确定性编号、首次到访年月与到访次数。
- 常见品牌只作为用户快速填写的纯文字候选，不使用商标图形，并明确不代表合作。

## 验收闭环

1. 相机或相册选择照片并生成可恢复草稿。
2. 未完成四项必填信息时得到字段级说明，不能误保存。
3. 选择经典奶茶/咖啡、糖度、冷热或冰量并保存。
4. 日历出现照片贴纸，详情可看到新增信息。
5. 同一店铺重复记录只累计次数，不重复生成店铺色票；新店生成不同编号与色票。
6. Lint、类型检查、单元测试与 Android 原生构建通过。
